## Validation and caveat

All six parsers completed without an exception. The generated tree node counts were:

| Parser | Nodes |
|---|---:|
| Kotowari | 104,120 |
| Pidgin | 100,001 |
| Sprache | 100,001 |
| SpracheJSON | 104,120 |
| Superpower | 100,001 |
| System.Text.Json | 100,001 |

Kotowari and the legacy SpracheJSON package both produce 4,119 more nodes than the other parsers, likely around empty containers. This exact match indicates that the difference is inherited JSON-parser behavior rather than a Kotowari-only benchmark adapter difference. The timings are retained as observations, but comparisons across the two node-count groups should not yet be presented as strictly equivalent workloads.

SpracheJSON 1.0.1 targets .NET Framework and places its parser assembly under `lib/net47`; the benchmark references that assembly explicitly while running on .NET 10. NuGet therefore reports `NU1701`, and BenchmarkDotNet's optimization validator is disabled so the legacy assembly can be measured. The SpracheJSON row was measured separately under the same `ShortRun` settings, so its ratio is calculated from the recorded means and has no combined-run `RatioSD`.
