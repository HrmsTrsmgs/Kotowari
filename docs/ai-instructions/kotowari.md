# Kotowari固有作業指示

## プロジェクトの目的

Kotowariを、第三者がビルド、テスト、利用、レビューできる、依存関係のないC#用パーサーコンビネーターライブラリとして整備する。

* 公開APIの理解しやすさ、組み合わせやすさ、診断可能性、テスト可能性を優先する。
* ライブラリ本体を特定の構文やデータ形式へ結合しない。
* 必要性が確認できない抽象化、汎用化、依存関係を追加しない。

## 公開APIと互換性

* 公開APIの変更前に、既存利用コード、テスト、サンプル、対象フレームワークへの影響を確認する。
* テストのためだけに公開範囲を広げない。
* `netstandard2.0` と `net10.0` の双方を対象とする構成を維持し、片方だけで利用可能なAPIを導入する場合は影響を明示する。
* パッケージの依存関係を増やす変更は、dependency-freeという製品特性への影響を確認する。テストやベンチマークだけの依存とは区別する。

## JSONサンプルとベンチマーク

* JSONパーサーはKotowariの使用例および性能比較用であり、ライブラリ本体の目的と混同しない。
* ベンチマークでは、入力ファイル、サイズ、ハッシュ、環境、ランタイム、依存バージョン、ジョブ設定を記録する。
* 比較対象が入力全体を消費し、結果を生成したことを測定前に検証する。部分解析や失敗したアダプターの時間を比較結果に含めない。
* 専用パーサーとパーサーコンビネーターを同列の主比較として扱わず、専用パーサーは参考値と明記する。
* 生成結果や処理量が異なる場合は差を記録し、厳密に同一の仕事量であると断定しない。
* 旧比較対象を残す場合は、互換性警告、手動参照、検証緩和など現行環境で必要な条件を隠さない。
* 単発値で一般的な優劣を断定せず、同一環境・同一入力・同一測定条件で観測した結果として報告する。

## 文書と公開準備

* READMEのビルド、テスト、ベンチマーク手順を実在する構成と一致させる。
* 未実装機能や未確認の互換性を利用可能なものとして記載しない。
* ライブラリ本体、テスト用JSONパーサー、ベンチマーク用アダプターの責務を文書上でも区別する。
