# 工程担当の共通規則

Red・Green・Refactorは同じ作業ツリー上で順番に行う。目的は履歴の分離であり、
相互相談、AIレビュー、AI承認を増やすことではない。担当は自工程だけを完了させ、
他工程を兼任せず、子エージェントへ再委任しない。

* `AGENTS.md`、`../common.md`、ユーザーが確定した契約、安全・Git規則を維持する。C#・Kotowari固有の指示と設計資料は必要な範囲を担当自身が読む。
* 工程指示として読むのはこの文書と自工程の文書だけとする。`run.md`、他工程の指示、会話全文、不採用案、モデル選択の議論を読み込まない。
* 要求、確定事項、提案、推測、未確認事項を区別する。未決定の外部契約が不可欠なら停止し、必要な判断だけを返す。
* 既存の未コミット・ステージ済み差分を保全し、ユーザーの変更を無断で上書き・コミットしない。
* Redは対象テストを実行して意図した失敗を確認する。Green・Refactorは対象・関連テストに加え、原則として全テスト、ビルド、静的検査を実行する。残りへ影響しないと依存関係や実行経路から説明できる場合だけ省略し、理由を報告する。
* 成功、失敗、Skip、未実行を区別する。同じコード・設定・実行条件で済んだ検証を受け渡しだけのために繰り返さない。必要な変更後の再検証は省略しない。
* Green後と実変更を伴うRefactor後は未コミット差分を人間が確認する。担当はステージ・コミットせず、対象ファイル、差分の要点、メッセージ案を進行役へ返す。

引き継ぎは成果物の場所・識別子、確定契約、実行したコマンドと結果、停止理由に絞る。
長い思考過程や会話要約、遵守宣言を次工程へ渡さない。
