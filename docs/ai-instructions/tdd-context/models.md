# モデル選択の開始方針

モデル選択は進行役だけが扱い、工程担当へ価格比較や選択過程を渡さない。工程名だけでモデルを固定しない。実際のモデルID、利用可否、推論設定、明示的なモデル指定の権限は起動時の環境で確認する。この文書は設定済みの証明ではない。

* Luna: 定型的なテスト展開、契約が明確な通常Green、明らかな重複除去、局所的な命名・可読性の整理。
* Sol: 新しい外部APIの設計、call siteの意味判断、共通化の可否、責務・抽象化・依存関係の判断、通常の構造的Refactor。
* Astra: 問題設定・主要制約・観測事実が揃い、Solでは扱い切れない広範囲・多制約の難問だけを候補にする。「重要」「上流」「原因不明」だけでは選ばない。

情報不足はモデル変更ではなく必要資料の取得で解消する。モデルや推論量の変更は、利用環境で許可された設定とユーザーの指定に従う。工程中に細かくモデルを交代させない。

これはTDD工程の開始方針であり、性能調査・チューニングの担当や推論設定を決める規則ではない。性能計測の担当は `../common.md` の指示に従う。
